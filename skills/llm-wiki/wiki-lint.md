# Operation 4: wiki-lint (Two-Phase Automated Health Maintenance)

## Goal
Maintain wiki structural health automatically through two complementary phases.
Phase A is fast and runs after every ingest — fixing immediate issues before they compound.
Phase B is deep and runs every 3 ingests — optimizing cross-references and surfacing
concept candidates for wiki-query exploration.

## Prerequisites
- `wiki-init` completed
- At least one `wiki-ingest` completed
- `PERSONA.md` and `SCHEMA.md` readable

## Trigger Mechanism

| Phase | Trigger | Automation |
|-------|---------|------------|
| **Phase A** | After every `wiki-ingest` completes | Automatic (no user action needed) |
| **Phase B** | After every 3 ingests (configurable via `PERSONA.md` `lint_phase_b_trigger`) | Automatic (runs after Phase A when counter reaches threshold) |

**Ingest Counter**: Stored in `PERSONA.md` as `ingest_counter`. Incremented by `wiki-ingest` Phase 5. Reset to 0 when Phase B runs.

---

## Phase A: Post-Ingest Quick Fix (Automated, Every Ingest)

### Goal
Fix immediate structural issues created during ingest before they compound across future ingests. This phase is FAST and NON-INTERACTIVE — all fixes are auto-applied without user confirmation.

### Step A.0: Pre-Lint State Check

Before running any lint checks:
1. Verify no `[IN-PROGRESS]` markers exist in `wiki/log.md` — if found, wait or abort
2. Verify `wiki/keyword-index.json` exists and is valid JSON — if missing/invalid, rebuild from all `raw/*/chunks.json` files
3. Verify `PERSONA.md` is parseable YAML — if corrupted, flag as critical and abort lint
4. If any check fails that cannot be auto-recovered: report to user and abort

### Step A.1: Scan for Broken Links

Search all `wiki/pages/*.md` for `[[...]]` patterns. For each link:
1. Check if target file exists in `wiki/pages/`
2. If target does NOT exist:
   - If it's a `[[concept-*]]` link: Remove the link (concepts are conversation-driven, not auto-created)
   - If it's a `[[topic-*]]` or `[[chunk-*]]` link: Check if it's a typo (fuzzy match existing pages)
   - If fuzzy match found: Auto-fix to correct slug
   - If no match: Remove the broken link and replace with plain text

### Step A.2: Fix Malformed Pages

For all pages created in the most recent ingest:
1. Verify frontmatter has all required fields (`title`, `tags`, `sources`, `updated`)
2. Add missing fields with sensible defaults
3. Remove any empty pages (0 content after frontmatter)
4. Verify all chunk pages have `## Chunk Text` section with content

### Step A.3: Cross-Link Similar Topic Pages

This is the key structural improvement. For each new topic page created in this ingest:
1. Extract keywords from the topic page title and content
2. Search existing `wiki/pages/topic-*` pages from OTHER sources for keyword overlap
3. If overlap score > 60% (shared keywords / total keywords):
   - Add a `## Related Topics` section to BOTH pages (if not already present)
   - Add `[[topic-other-source-t]]` links with brief relationship note

**Cross-link template** (appended to topic pages):
```markdown
## Related Topics (Cross-Source)
<!-- Auto-generated by lint Phase A -->
| Related Topic | Source | Relationship |
|---------------|--------|--------------|
| [[topic-<other-slug>-<t>]] | [[source-<other-slug>-map]] | Discusses same subject from different source |
```

### Step A.4: Merge Exact Duplicates

If two pages have:
- Identical titles (case-insensitive)
- Same content structure
- Created from same ingest (accidental duplicate)

Merge into one page, keeping the most complete version. Delete the duplicate.

### Step A.5: Auto-Apply & Log

All Phase A fixes are applied automatically (no user confirmation):
1. Apply all fixes
2. Append brief entry to `wiki/log.md`:

```markdown
## [YYYY-MM-DD] lint-phase-a | Post-Ingest Quick Fix
- Broken links fixed: <N>
- Malformed pages fixed: <N>
- Topic cross-links added: <N>
- Duplicates merged: <N>
- Orphan pages connected to index: <N>
- Total auto-fixes: <N>
```

### Step A.6: Verify Index Connectivity

Ensure every page in `wiki/pages/` is reachable from `wiki/index.md` within 2 hops:

1. Read `wiki/index.md` — build a list of all directly linked pages
2. For each `source-<slug>-map.md` linked from index, read it and collect all pages it references
3. Combine into "reachable set" (all pages linked from index directly + all pages linked from source maps)
4. List all files in `wiki/pages/` directory
5. For each page NOT in the reachable set:
   - If it has `sources: [<slug>]` in frontmatter → add to the corresponding `source-<slug>-map.md` "All Pages from This Source" section
   - If it has no source (e.g., concept page) → add to `wiki/index.md` under "Expanded Concepts"
   - If it's a query page → add to `wiki/queries.md`
6. Log orphan connections

**Update Phase A log entry** to include orphan fix count:
```markdown
## [YYYY-MM-DD] lint-phase-a | Post-Ingest Quick Fix
- Broken links fixed: <N>
- Malformed pages fixed: <N>
- Topic cross-links added: <N>
- Duplicates merged: <N>
- Orphan pages connected to index: <N>
- Total auto-fixes: <N>
```

### Step A.7: Verify Keyword Index

1. Read `wiki/keyword-index.json`
2. For each entry, verify the referenced chunk page exists in `wiki/pages/`
3. Remove entries pointing to deleted or renamed chunk pages
4. Scan all chunk pages for keywords not yet in the index (from new chunks created during ingest)
5. Add missing entries
6. Update `_meta.updated` and `_meta.total_keywords`

## Phase B: Deep Cross-Link Audit (Automated, Every 3 Ingests)

### Goal
Comprehensive wiki health audit covering cross-references, concept candidate detection,
orphan resolution, and multi-source relationship optimization. Produces a full report
and presents fix options to the user for non-trivial changes.

### Step B.1: Full Inventory Building (Main Agent)

#### B.1.1: Read index.md

Read `wiki/index.md` in full. Build:
- List of all source maps: `source-*-map`
- List of all expanded concepts: `concept-*`
- List of all topic pages: `topic-*`
- List of all relations pages: `relations-*`
- List of query pages: `query-*`
- List of lint pages: `lint-*`

#### B.1.2: Scan pages/ Directory

List all files in `wiki/pages/`. Build:
- Complete slug inventory
- File count by type (chunk, concept, topic, source-map, relations, query, lint)

#### B.1.3: Scan raw/ Directory

List all sources in `raw/`. For each:
- Verify `chunks.json` exists
- Verify `toc.md` exists
- Verify `metadata.json` exists
- Count chunks in `chunks.json`

#### B.1.4: Build Cross-Reference Map

Search all `wiki/pages/*.md` for `[[...]]` patterns. Build:
- Outbound links per page
- Inbound links per page (reverse index)
- Orphan pages (zero inbound links)
- Broken links (outbound to non-existent slugs)

**Do NOT read full pages for this.** Use grep/search with context lines only.

### Step B.2: Parallel Subagent Checks

Dispatch subagents for parallel checking.

#### Subagent A: Critical Errors

**Input**: Slug inventory, cross-reference map, raw/ directory listing

**Checklist**:
- [ ] **Broken links** — `[[slug]]` with no corresponding file (should be rare after Phase A)
- [ ] **Missing frontmatter** — pages without `title`, `tags`, `sources`, or `updated`
- [ ] **Missing chunk maps** — source cited but `raw/<slug>/chunks.json` absent
- [ ] **Broken paragraph anchors** — chunk ID not found in source's chunk map
- [ ] **Missing chunk pages** — `chunks.json` has chunk IDs that passed salience but no wiki page
- [ ] **Empty chunk pages** — chunk page exists but has no verbatim text
- [ ] **Orphan source maps** — `source-*-map` not linked from `index.md`
- [ ] **Stale concept pages** — `status: expanded` but zero source evidence sections

**Output format**:
```yaml
category: errors
count: <N>
items:
  - severity: critical
    type: broken-link
    page: "wiki/pages/concept-X.md"
    link: "[[concept-Y]]"
    fix: "Remove link or create via wiki-query conversation"
```

#### Subagent B: Warnings

**Input**: Page inventory, frontmatter summaries, cross-reference map

**Checklist**:
- [ ] **Orphan pages** — zero inbound `[[slug]]` links for 30+ days
- [ ] **Orphan expanded concepts** — `status: expanded` with zero inbound links
- [ ] **Contradictions** — claims in one page conflict with another (check relations pages)
- [ ] **Stale claims** — not updated in 90 days, contains "latest" or old year literals
- [ ] **Unfootnoted topic claims** — topic pages with factual claims lacking citations
- [ ] **Chunk pages without extracted concepts candidates** — no concept candidate mentions
- [ ] **Relations pages without cross-source links** — only intra-source relationships
- [ ] **Metadata drift** — `metadata.json` date differs from source file modification date
- [ ] **Missing topic cross-links** — similar topics from different sources not yet linked (Phase A gaps)

**Output format**:
```yaml
category: warnings
count: <N>
items:
  - severity: warning
    type: missing-topic-crosslink
    page: "wiki/pages/topic-<slug>-<t>.md"
    similar_to: "wiki/pages/topic-<other-slug>-<t>.md"
    fix: "Add cross-link in Related Topics section"
```

#### Subagent C: Concept Candidates & Optimization

**Input**: Page inventory, all source maps' "Concept Candidates" sections, cross-reference map, `PERSONA.md`

**Checklist**:
- [ ] **High-priority concept candidates** — topics appearing across 3+ sources without a concept page
- [ ] **Convergence patterns** — multiple topic pages from different sources discussing same subject
- [ ] **Coverage gaps** — open questions in `overview.md` answerable by existing sources
- [ ] **Missing cross-references** — two pages discuss same entity but don't link
- [ ] **Underutilized sources** — source ingested but few chunk pages created (below cap)
- [ ] **Index.md bloat** — too many sections, consider reorganization
- [ ] **Persona mismatch** — pages not following persona-specific conventions

#### Stale Draft Concept Detection
- Scan `wiki/pages/concept-*.md` for pages with `status: draft`
- For each draft concept, check creation date vs current `ingest_counter`
- If draft was created > 3 ingests ago and never promoted to `expanded`:
  - Surface as suggestion: "Consider exploring or archiving these stale draft concepts: [list]"
  - Recommend: run wiki-query Concept Discovery on these, or archive if no longer relevant

**Output format**:
```yaml
category: concept_candidates
count: <N>
items:
  - severity: info
    type: concept-candidate-ready
    candidate: "attention-mechanisms"
    sources: ["paper-a", "paper-b", "paper-c"]
    related_topics: ["topic-paper-a-§3", "topic-paper-b-§2", "topic-paper-c-§4"]
    suggestion: "This topic appears across 3 sources with high convergence. Explore via wiki-query for potential concept discovery."
```

#### Subagent D: Relations Page Refinement

**Input**: All `relations-*.md` pages, all topic page cross-links (from Phase A), all source maps

**Checklist**:
- [ ] **Missing relationship entries** — topic cross-links (from Phase A Step A.3) that imply relationships not yet recorded in any relations page
- [ ] **Stale relationships** — entries referencing archived or deleted chunks
- [ ] **Incomplete cross-source coverage** — relations pages that only have intra-source entries despite multiple sources covering the same topics
- [ ] **Relationship type gaps** — detected patterns (contradicts, extends, supports) visible from topic content but not recorded in relations tables
- [ ] **Unidirectional relationships** — if Source A's relations page mentions Source B, but Source B's relations page doesn't mention Source A

**Task**: For each gap found, add the missing relationship entry to the appropriate `relations-<slug>.md` page. Relations pages are living documents that must be refined on every Phase B run.

**Output format**:
```yaml
category: relations_refinement
count: <N>
items:
  - type: missing-relationship
    relations_page: "wiki/pages/relations-<slug>.md"
    from: "[[chunk-<slug>-<id>]]"
    to: "[[chunk-<other-slug>-<id>]]"
    relationship_type: "extends | contradicts | supports | refines"
    evidence: "<brief evidence>"
    fix: "Add to Cross-Source Relationships table"
```

### Step B.4: Apply Fixes (After User Confirmation)

For confirmed auto-fixable items:
1. Make the change
2. Log the fix in the lint report
3. Append to `wiki/log.md`

**Auto-fixable items include:**
- Missing chunk pages (on-demand compilation from chunks.json)
- Missing frontmatter fields (add defaults)
- Orphan source maps not in index.md (add to index)
- Missing topic cross-links (add Related Topics section)

**Never auto-fix without confirmation in Phase B:**
- Broken links that might indicate needed concept pages
- Contradictions (require human judgment or wiki-query exploration)
- Content changes

### Step B.5: Reset Counter & Log

1. Reset `ingest_counter` to 0 in `PERSONA.md`

## Subagent Dispatch Strategy

### Phase A Dispatch (No subagents needed — fast single-pass)

Phase A is lightweight enough to run without subagents:
1. Grep for `[[...]]` patterns
2. Check file existence
3. Compare topic keywords
4. Apply fixes
5. Log

### Phase B Dispatch (4 parallel subagents)

| Check Category | Subagent | Input Size | Parallelizable |
|---------------|----------|------------|----------------|
| Critical errors | A | All pages + raw/ | Yes |
| Warnings | B | All pages + relations | Yes |
| Concept candidates + optimization | C | All pages + source maps + index | Yes |
| Relations refinement | D | All relations pages + topic cross-links | Yes |

**Main Agent Coordination:**
```
Phase A (no subagents):
  1. Scan broken links → fix
  2. Fix malformed pages
  3. Cross-link similar topics
  4. Merge duplicates
  5. Log

Phase B (4 subagents):
  1. Build full inventory
  2. Dispatch 4 subagents in parallel
  3. Receive structured outputs
  4. Merge into unified report
  5. Apply relations refinements (auto-fix — these are structural additions, not content changes)
  6. Present fix options + concept candidates to user
  7. Apply confirmed fixes
  8. Reset counter, log, report
```

## Common Mistakes to Avoid (Lint)

- **Skipping Phase A after ingest** — Phase A is mandatory and automated; never skip it
- **Running Phase B too frequently** — every 3 ingests is the default; more frequent is wasteful
- **Reading every page in full during Phase A** — use grep/search only for cross-references
- **Auto-fixing concept-related broken links by creating stubs** — concepts are conversation-driven; remove the link instead
- **Not cross-linking similar topics** — this is Phase A's most important job
- **Not surfacing concept candidates in Phase B** — the whole point is to feed wiki-query
- **Writing Phase B lint report without concept candidates section** — always include it
- **Auto-fixing content changes in Phase B without confirmation** — structural fixes only in Phase A; content changes need user approval
- **Not checking raw/ directory in Phase B** — missing chunks.json is still a critical error
- **Ignoring the ingest counter** — Phase B depends on accurate counter tracking
- **Not resetting counter after Phase B** — will cause Phase B to trigger on next ingest
- **Forgetting to log Phase A** — both phases must be traceable in log.md
- **Not running Step A.0 state check before lint** — risks operating on corrupted state
- **Forgetting to verify keyword index (Step A.7) after lint fixes that delete or rename pages**
- **Ignoring stale draft concepts** — they accumulate if never explored or archived
- **Using deprecated placeholder formats** — use only PENDING or NO-DATA standard
